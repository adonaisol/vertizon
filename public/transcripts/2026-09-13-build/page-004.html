Section 3: The UI

Layout: map on the left (~60%), a right panel that is either the agenda (default) or the employee drilldown (after clicking a point). Top bar: title, a one-line "how to read this", and a key icon for BYOK.

The map. X = evidence strength (1–4), Y = manager rating (1–4). Each point is an employee, coloured by manager. Points are jittered slightly since both axes are integers. The diagonal is "rating matches evidence". Per-manager fitted line, toggleable via the legend. Hollow points = low sufficiency. Hover shows name, manager, and the two numbers.

What the three problems look like: far off the diagonal = individual mismatch; a manager's line sitting above/below the others = lenient/harsh; lines with different slopes = the bar for "Exceeds" differs. The agenda panel says this in words so nobody has to read the chart cold.

Agenda panel: cases ranked by |rating − strength|, weighted down by low sufficiency. Three groups: Discuss (mismatch, sufficient evidence), Get more input (low sufficiency), Looks consistent. Each row states the reason in one sentence.

Drilldown panel: 1. The review text with evidence quotes highlighted, coloured by dimension. Clicking a quote shows its rationale and level. 2. Override: each evidence item's level can be changed by the facilitator; strength recomputes and the point moves on the map. This is the human-in-the-loop part. 3. "Under other managers' bars": a small row per manager: the rating range this employee's evidence would imply under that manager's fitted line, with "based on N reviews" and a wide band when N is small. 4. Re-run with Claude (needs key): calls the API, shows the new extraction next to the bundled one with changed items marked.

Stack detail: Recharts for the scatter (or plain SVG if Recharts fights the fitted lines; I'll decide when building), Tailwind, no state library, useReducer for overrides.
